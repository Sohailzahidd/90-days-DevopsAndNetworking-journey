---

## What is Repository Management?

Repository management is the process of organizing, maintaining, securing, and documenting a GitHub repository so that it is easy to understand, contribute to, and maintain.

A well-managed repository improves collaboration and makes projects easier to maintain over time.

---

## Repository Visibility

GitHub repositories can be:

- Public
- Private

Public repositories are visible to everyone, while private repositories are restricted to invited collaborators.

---

## README

The README file serves as the primary documentation of a repository.

It typically includes:

- Project overview
- Features
- Installation
- Usage
- Folder structure
- Technologies used
- License

---

## LICENSE

A license defines how others can use, modify, and distribute your project.

Common licenses include:

- MIT
- Apache 2.0
- GPL

---

## .gitignore

The .gitignore file specifies files and directories that Git should ignore.

Examples include:

- Log files
- Build artifacts
- Environment files
- IDE settings

---

## Git Tags

Tags are used to mark important versions of a project.

Example:

v1.0.0

They are commonly used when creating software releases.

---

## GitHub Releases

A release represents a stable version of the project.

Releases usually contain:

- Version number
- Release notes
- Downloadable source code

---

## Collaborators

Repository owners can invite collaborators with different permission levels.

Common permissions include:

- Read
- Write
- Maintain
- Admin

---

## Branch Protection

Branch protection rules help secure important branches by requiring Pull Requests, code reviews, and passing CI checks before merging.

---

## Repository Insights

GitHub provides repository analytics such as:

- Contributors
- Traffic
- Commits
- Network Graph
- Dependency Graph

These insights help maintain project health.

---

## Outcome

Learned how professional repositories are organized and managed using GitHub's repository management features.
